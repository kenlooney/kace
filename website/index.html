01 / THE PROJECT

Made for the
curious.

KACE is a place to get closer to the process of building programming tools.

Short for Ken’s Assembly and Compiler Environment, KACE is a framework for creating assemblers and compiler front ends. It brings together the building blocks that turn text into structure, meaning, and eventually machine-readable output.

It’s an evolving project built around learning, experimentation, and the joy of understanding what happens beneath the surface.

03 / THE ASSEMBLER

BUILT WITH KACE ↗

Say hello
to KASM.

An assembler with a more readable meaning for expressing instructions.

KASM is the first assembler being developed with KACE. It explores familiar assembly ideas alongside a language that has more meaning and syntax then your typical assemblers. The language created for the assembler is ment to be very user and kid friendly with simple and intuitive constructs, making it easier to understand and use. My goal is to have it great as a learning tool that young people can pick up easily and enjoy.

Choices that read a little more naturally—like using sum for addition or copy and move as aliases for mov. Write byte 5, definebyte 5, or the familiar db 5 to emit a byte.

Repeat bytes with fill 4 byte 0; times, repeat, and dup work too. For padding, fill 10 - (currentposition - sectionstart) byte 0 fills to offset 10. The shorter $ and $$ spellings are also supported. Repetition currently emits bytes only, with a limit of one million per directive. In flat output, sectionstart is zero.

Organize a program across files with #include "data/extra.asm". Included files can include others, and their statements share the program's labels and output. Relative paths are resolved from the file containing the directive; include cycles are reported as errors.

KASM can resolve short and near jumps to labels before or after an instruction. Use jmp short or jmp near; jump and goto are aliases for jmp. KASM also assembles and disassembles 16-bit far jumps such as jmp far 0x1234:0x5678, using numeric segment and offset values.

Short conditional jumps make it possible to branch based on CPU flags. Use ifequal (jz), ifnotequal (jnz), ifcarry (jc), or ifnotcarry (jnc). For example:

start:
    ifequal done
    nop
done:
    ifnotequal start

This assembles to 74 01 90 75 FB. The conditions check flags set by earlier instructions, and the target must be within the short jump's signed-byte range. Conditional disassembly currently shows canonical names and numeric displacements, such as jz 1.

When an expression has a supported arithmetic error, KASM can show the source line and point to the problem. For example:

example.asm:1: Division by zero
byte 10 / 0
          ^

Division and modulo by zero point to the divisor; arithmetic overflow and negative subtraction point to the start of the expression. Other errors do not yet all include a source span.

Load a value from memory using a base register. KASM supports these initial x86 forms:

code16
mov ax, [bx]     ; 8B 07
code32
mov eax, [ebx]   ; 8B 03
code64
mov rax, [rbx]   ; 48 8B 03

In 16-bit mode, the supported bases are bx, si, and di. The 32- and 64-bit forms also support stack-pointer bases. They can use a base plus a scaled index:

code32
mov eax, [ebx + ecx * 4]        ; 8B 04 8B
move eax, [ebx sum (ecx mul 4)] ; same bytes
code64
mov rax, [rbx + rcx * 4]        ; 48 8B 04 8B

Scales can be 1, 2, 4, or 8. Parentheses around the scaled index work; expressions such as [(ebx + ecx) * 4] are not supported yet. The index cannot be esp or rsp, and ebp/rbp cannot be a base in these forms. Displacements, extended registers, and memory stores are still ahead. A matching symbol file lets disassembly follow recorded mode changes; without mode metadata it uses the selected CPU mode.

Request a software interrupt with int (or interrupt) and use hlt (or halt) for the x86 halt instruction:

int 0x21  ; CD 21
halt      ; F4

Interrupt vectors are integer literals from 0 through 255; their meaning depends on the execution environment. Disassembly uses int and hlt and displays the interrupt vector in decimal. The halt instruction requires appropriate CPU privileges at runtime.

The KASM CLI can also disassemble supported x86 instructions into a .dism file. Assembly saves labels, source locations, and byte ranges in a matching .sym file. The disassembler can restore short- and near-jump targets and show source locations for matching instruction ranges. A generated header records the time in UTC. For example:

; Generated by the KASM disassembler
; Generated at: 2026-11-12 12:00:00 UTC

start:
; source: example.asm:2:1
jmp short done

The timestamp and source path depend on the run. Without matching source records, disassembly omits source comments; without symbols, short and near jumps show their relative displacement. Older symbol files can still be read. Disassembly uses standard instruction names like jmp, even when the source used an alias such as jump or goto.

KASM / REFERENCE

Meet the directives.

Directives describe data and guide assembly. Here's what KASM supports today.

Define a byte

byte 42

Emit one byte from an expression. definebyte and db are aliases; the value must fit in a byte.

Repeat and pad

fill 4 byte 0

times, repeat, and dup also repeat bytes. Counts may use currentposition and sectionstart to pad to an offset. Repetition is limited to one million bytes per directive.

Include a file

#include "data/extra.asm"

Insert another source file during source expansion. Nested includes share the program's labels and output; relative paths start from the including file, and cycles are rejected.

Check a position

#assertposition 2

During assembly, check that the output is at the specified byte offset. The argument is an integer literal; the directive emits no bytes and reports an error if the position differs.

byte 1
byte 2
#assertposition 2  ; passes after two bytes
byte 3

The output is 01 02 03; the assertion adds no bytes.

04 / CPU PLUGINS

One framework.
Room to grow.

CPU plugins give KASM a way to work with different architectures. Select a plugin by name when assembling, or build one for a new CPU.

HOW IT FITS TOGETHER

One CLI. Different machines.

KASM reads your source and hands its statements to the selected plugin's assembler. The plugin handles its own instruction encoding and jump fixups. For disassembly, the CLI hands the bytes and any symbols to the plugin's disassembler.

SOURCEKASMSTATEMENTS →Assembler→ BYTES
BINARYKASMBYTES →Disassembler→ TEXT
Assembler and disassembler are provided by the selected CPU plugin.

INCLUDED WITH KASM

  • x86DEFAULT CPU

    The assembler supports nop, int, hlt, memory loads, short unconditional and conditional jumps, mode-aware near jumps, and 16-bit far jumps. The CLI can disassemble supported immediate moves, register-to-register moves, memory loads, and those jump forms. Conditional jumps disassemble with numeric displacements.

    Source statements code16, code32, and code64 select the mode for subsequent assembly. Near jumps use a 16-bit displacement in 16-bit mode and a 32-bit displacement in 32- and 64-bit modes. The symbol file records modes for disassembly; raw binaries do not.

    The x86 register file groups overlapping names such as rax, eax, ax, al, and ah. The framework exposes register files while the plugin supplies x86-specific widths and encoding IDs.

    The assembler supports immediate moves to al, cl, dl, bl, ah, ch, dh, and bh, and the first eight 16- and 32-bit register groups. For example, in 16-bit mode mov cx, 0x1234 encodes as B9 34 12. The decoder supports those 8-bit moves and the first eight 16-, 32-, and 64-bit register groups; broader register and prefix support is still in progress.

    The x86 plugin can encode and decode register-to-register moves for the first eight register groups. Its native-width examples are:

    16-bit: mov ax, bx   → 89 D8
32-bit: mov eax, ebx → 89 D8
64-bit: mov rax, rbx → 48 89 D8

    These register-to-register encodings are available through the plugin API; KASM source assembly for them is still being developed. Extended registers and memory operands are not yet supported for this form.

Select the included plugin with --cpu=x86 or -c x86. x86 is selected by default.

ADDING A CPU PLUGIN

Bring another architecture.

  1. Provide a Cpu with a register file and an Assembler for your architecture and, optionally, a Disassembler.
  2. Build it as a shared library and export the C factory functions create_cpu and destroy_cpu.
  3. Place the library next to the KASM executable. Use the platform’s shared-library naming convention, such as x86.dll on Windows or libx86.so on Linux.
  4. Select it with --cpu=<name> when producing output.

The plugin interface and shared statement model are still evolving; plugins must be built against the matching KACE interface.
