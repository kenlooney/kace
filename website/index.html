01 / THE PROJECT

Made for the
curious.

KACE is a place to get closer to the process of building programming tools.

Short for Ken’s Assembly and Compiler Environment, KACE is a framework for creating assemblers and compiler front ends. It brings together the building blocks that turn text into structure, meaning, and eventually machine-readable output.

It’s an evolving project built around learning, experimentation, and the joy of understanding what happens beneath the surface.

03 / THE ASSEMBLER

BUILT WITH KACE ↗

Say hello
to KASM.

An assembler with a more readable meaning for expressing instructions.

KASM is the first assembler being developed with KACE. It explores familiar assembly ideas alongside a language that has more meaning and syntax then your typical assemblers. The language created for the assembler is ment to be very user and kid friendly with simple and intuitive constructs, making it easier to understand and use. My goal is to have it great as a learning tool that young people can pick up easily and enjoy.

Choices that read a little more naturally—like using sum for addition or copy and move as an alias for mov and define to define byte widths. Instead of using db, which is ambiguous, the language opts for more descriptive constructs. Is db supposed to mean drop byte or define byte? it has no meaning! It’s about making the code more understandable and meaningful for the user.

KASM can now resolve short jumps to labels before or after an instruction. Use jmp short, jump short, or goto short to make the destination clear. Near and far jumps are still in development.

The KASM CLI can also disassemble supported x86 instructions into a .dism file. Assembly saves labels in a matching .sym file, which the disassembler can use to restore jump targets. Without that file, jumps show their relative displacement. Disassembly uses standard instruction names like jmp, even when the source used an alias such as jump or goto.

04 / CPU PLUGINS

One framework.
Room to grow.

CPU plugins give KASM a way to work with different architectures. Select a plugin by name when assembling, or build one for a new CPU.

INCLUDED WITH KASM

  • x86DEFAULT CPU

    The assembler supports nop and short jumps. The CLI can disassemble nop, mov al with an immediate, and short jumps. The plugin can also encode immediate mov al, but that encoding is not yet connected to the CLI.

Select the included plugin with --cpu=x86 or -c x86. x86 is selected by default.

ADDING A CPU PLUGIN

Bring another architecture.

  1. Override the KACE Cpu operations supported by your target architecture; the default implementations report unsupported operations.
  2. Build it as a shared library and export the C factory functions create_cpu and destroy_cpu.
  3. Place the library next to the KASM executable. Use the platform’s shared-library naming convention, such as x86.dll on Windows or libx86.so on Linux.
  4. Select it with --cpu=<name> when producing output.

The plugin interface and supported instructions are still evolving.
